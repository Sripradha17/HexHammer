# Roadmap

Each phase adds levels. The Professional Skills and Interview tracks grow in every phase.

| Phase | Scope                                       | Runner types                                                                      |
| ----- | ------------------------------------------- | --------------------------------------------------------------------------------- |
| 1     | Level 1 (Red), classroom app, design system | Level 1: browser Web Worker                                                       |
| 2     | Levels 2-3 (Orange, Yellow) + DSA track     | Level 2: browser Web Worker. Level 3: browser Web Worker + guided local exercises |
| 3     | Levels 4-5 (Green, Blue)                    | Level 4: sandboxed iframe. Level 5: local-only server runner                      |
| 4     | Levels 6-7 (Indigo, Violet)                 | Level 6: sandboxed iframe. Level 7: guided, local first (AWS free plan)           |
| 5     | Level 8 (Gold) + public browser-only deploy | Level 8: local Ollama only                                                        |

Level 2, Level 3, the DSA track, Level 4, Level 5 and the start of Level 6 were all written early, ahead of their phases. Interview Packs are done for Levels 1 through 5 (Level 3's Solve-It is a retry/timeout helper, Level 4's is three accessibility/safety pure-logic functions, Level 5's is a tiny Express-style router — all worker-runnable by design, since the Interview page always uses the plain Worker runner, even for a level whose own strikes use a different one). The DSA track has 14 strikes, one per topic. Level 4 is content-complete: 17 strikes covering all 20 planned topics (three closely related pairs are combined into one strike each: keyboard+ARIA, WCAG+screen-reader, CSP+CORS), with its own sandboxed iframe runner built ahead of schedule. Level 5 is content-complete too: all 37 planned topics, with two local runners of its own, also built ahead of schedule: `apps/api/src/serverRunner/runServerCode.ts` (real Express — HTTP, every Middleware topic, both REST design topics, every Auth topic bar OAuth/OIDC, most Security topics, the N+1 problem, Redis caching (simulated with an in-memory Map, a deliberate exception — see below), background jobs, WebSockets (`ws`), file uploads (`multer`), logging, GraphQL (`graphql`), and OpenAPI docs) and `apps/api/src/serverRunner/runSqlCode.ts` (real SQL against a throwaway IN-MEMORY database via `pg-mem` — joins, group by, transactions). Password hashing and hand-built signed tokens use only Node's built-in `crypto` module, no dependency. Ten topics stayed guided-local instead of live-graded, each for an honest reason documented in `packages/content/level-5/index.ts`: pg-mem does not implement `EXPLAIN` at all, OAuth/OIDC and CSRF need a real external provider or cross-site browser this offline classroom cannot reach, and several (the use()/next() chain, Prisma ORM, API testing with supertest, OWASP Top 10, NoSQL modeling) are concept surveys rather than single exercises.

**Level 6 (React) has its first 5 strikes** (of 21 planned: Components and props, State, Effects, Custom hooks, Context) and its own runner, built ahead of schedule: real React/ReactDOM/Babel standalone, bundled locally by `apps/web/scripts/build-react-env.mjs` (React 19 dropped the old ready-made browser build, so there is no CDN shortcut — this app stays fully offline either way) and run inside the exact same sandboxed iframe Level 4 already uses. Unlike every earlier level, Level 6 lessons have **no automated starter-fails/solution-passes check**: happy-dom (the Node-side DOM every other in-browser runner's fairness check runs in) cannot actually run Babel-transformed JSX — confirmed empirically, its own script-element evaluator throws on the dynamically-injected `<script>` Babel creates. Each Level 6 lesson is instead verified by hand, in a real browser, as it is written. Building this surfaced two real, worth-knowing bugs along the way, both now fixed and documented in `reactIframeHarness.ts` and the lesson files themselves: React's render does not commit synchronously inside a `<script type="text/babel">` block (fixed with a shared `settle()` wait every test must call first), and firing two clicks back-to-back in one test can under-count a `setState` update by one, a real consequence of React batching state updates within a single synchronous tick when a component always reads the plain (non-updater-function) `count` from its own render closure.

## Warnings

- **Level 5 server runner:** running learner code on the server is dangerous. It is now built (`apps/api/src/serverRunner`) and is **local-only**: it refuses every request unless `NODE_ENV` is not `production` AND the request came from this same computer's own loopback address, and every server strike shows a permanent warning in the UI. The app must **never** be publicly deployed with it enabled.
- **Level 6 React runner:** lower-stakes than Level 5's (it never touches a real server or a real database — it is the same sandboxed iframe Level 4 already uses, just with React loaded into it), but has no automated fairness check (see above). Verify every new Level 6 lesson by hand in a real browser before trusting it.
- **Level 7 AWS:** use the AWS free plan only. It lasts up to 6 months or until credits run out, so open the account only when you reach Level 7. Every lesson must warn about cost traps and show how to tear down.
- **Level 8 AI:** local Ollama only, never a paid API.
- **Phase 5 public deploy:** browser-only build (no server runner, no database server).

## Tracks

- **DSA** starts at Level 2 (2-3 problems a week).
- **Professional Skills** is content-complete: all 9 planned topics, starting at Level 1. Mostly guided-local (workplace habits, not code), with two real hands-on exercises: a debugging method (a genuine off-by-one bug to find) and reviewing/verifying AI-generated code (a function that looks right and passes the obvious case, but was never tested against its real edge case — made concrete, tying directly to the charter's own stated goal).
- **Interview** grows every phase (system design drills from Level 5 on); Say-It/Solve-It/STAR packs are now done for Levels 1 through 5.
